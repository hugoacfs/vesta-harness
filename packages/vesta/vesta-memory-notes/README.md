# @deepseek-ai/dsh-vesta-memory-notes

Vesta fork, host plugin (roadmap T13, 2026-09-17). Automatic capture and recall over the memory MCP (`ai-memory-mcp`, loopback 7332): eligible root sessions accumulate their turns; after `idleSeconds` of idleness with at least `everyTurns` user turns, or on close or archive, one short model call proposes at most `maxPerPass` durable notes as JSON (preferences, decisions with reasons, stable facts, corrections, dated events — never task state, implementation detail or secrets), each is checked against the store with `memory_search` (a close note is updated by appending, otherwise a new note is created, tagged as auto-captured; every write passes `source: auto` and the session id, which a store with provenance fields (contract 3) keeps as the note's origin and older stores ignore), caps per session and per day apply, and every write is logged to `$DSH_HOME/memory-notes.log.jsonl`. Before every prompt (through the modes plugin's prompt router) the notes not yet shown ride that step as one injected message with their age (D19), so the request prefix stays cache-stable. A store with `memory_recall` (contract 4) chooses those notes itself: it gets the message, the previous user message as context and the names already shown, reranks its candidates and often returns none; with an older store the plugin searches the message and keeps the notes scoring at least `recallMinScore` and half the best score. Note bodies come from the JSON record `memory_read` returns (`src/note-record.ts`); records that capture nested inside bodies before 2026-10-01 (it appended updates to the whole record) are unwrapped, so recall shows the note's text and an update appends to the flat body. `/memory` shows status and recent automatic notes, `/memory now` captures, `/memory off|on` pauses the session, `/memory forget <name>` deletes a note (the store's git history keeps it). Incognito, routine, Batch and child sessions are never captured.
